How to use the Pelican admin portal.

How it works

Pelican crawls file shares, mailboxes and SharePoint sites into one search index, keeping each document's permissions, so people only find what they're allowed to see. Each thing it crawls is a source.

  • The portal holds the list of sources, their schedules, and who may manage them.
  • Workers do the crawling. They ask the portal for work, run it, and report back. You'll see their progress on a source's page and on Activity.
  • The portal never holds a password. Crawl accounts are kept on the workers; a source only says which one to use.
  • Each crawl only fetches what changed since the last one, so after the first crawl they're quick.

Who can do what

You sign in with your directory (AD) account.

  • Super admins can do everything: every source, scopes, credentials, settings, workers and the whole audit log.
  • Scoped admins manage the sources in their scopes, within the limits a super admin set on each scope. They don't see other sources.

Someone who is neither can't sign in. Group changes in AD apply the next time you sign in.

Adding a source

  1. On Sources, choose Add source and pick the type: SMB share, Exchange mailbox or SharePoint site.
  2. Name: how the source appears in search. Letters, digits, . _ -; it must be unique across all types.
  3. Scope: who besides super admins can manage it.
  4. Fill in where it is:
    • SMB share: the server, the share, and optionally a folder inside it (e.g. Finance\Reports). Pick the crawl account to sign in with.
    • Exchange mailbox: the mailbox address.
    • SharePoint site: the site's full address.
  5. Optional settings left at Default use the global settings for that type.
  6. For mail and SharePoint, Extra access adds people or groups on top of those who can already see it. In a scope, only the people and groups the scope allows can be added.
  7. Choose a schedule, or manual only.

Then use Test connection before the first crawl. The name and location can't be changed later, because every document carries them; to move a source, add a new one and remove the old.

Working with a source

Open a source from Sources. Its page shows its settings, how much of the index it takes, and its recent jobs.

  • Crawl now: crawl it straight away instead of waiting for its schedule.
  • Sync permissions (SMB): re-read folder permissions and update who can see each document, without downloading anything.
  • Test connection: sign in as the crawler would and read a little. Nothing is indexed.
  • Edit: change settings, scope (super admins), or schedule. Changes apply from the next job.
  • As the crawler sees it shows the exact settings a worker receives.

Disabling or removing a source

  • Disable (Edit, untick Crawl this source): no more crawls, but its documents stay searchable. Use this to pause a source.
  • Remove source… deletes everything the source indexed and forgets its crawl history. It shows how many documents will go and asks you to type the source's name. A worker then deletes them; the source disappears from the list when that's finished. This can't be undone or cancelled.

Jobs and logs

Every crawl, permission sync, connection test and removal is a job.

  • Queued: waiting for a worker with a free slot. Running: a worker has it. Done, Failed or Cancelled when it ends.
  • Result shows running totals while a job runs (updated every 15 seconds), e.g. 120 indexed · 4,500 unchanged · 4,620 found, and the final totals when it's done. For a failed job it shows the error.
  • Log opens the job's output. It keeps updating while the job runs.
  • Cancel stops a queued or running job. Removals can't be cancelled.
  • If a worker stops responding for two minutes, its job is marked failed and runs again at its next scheduled time. A failed removal is tried again after five minutes.

Activity lists jobs for all your sources from the last week.

Workers Super admins

The Workers table on Activity shows each worker, how many jobs it's running, and when it last checked in. A worker that hasn't checked in for two minutes is marked not responding; after an hour it leaves the list.

  • Jobs at once: each worker runs up to the default number of jobs at the same time. Change the default at the top, or give one worker its own number. Workers pick up changes within a few seconds; running jobs are never stopped.
  • More workers are added on the server, not in the portal: docker compose … up -d --scale worker=3.
  • Any free worker takes the next job. Connection tests go first, then removals, then crawls oldest first.

Storage

How big the index is and how much of it each source takes. Super admins also see disk space and growth.

  • Documents and Raw file size are exact.
  • Est. index size is an estimate: OpenSearch reports the size of the whole index, so it's split by each source's share of the stored data.
  • Sized below 100% means some documents were indexed before their size was recorded, so the estimate for that source is less certain.
  • Growth and Docs/day need about a day of history.
  • Figures refresh every 15 minutes. Super admins can use Refresh now, once a minute.

Scopes

A scope hands some sources to a team without making them super admins. Super admins create and edit scopes; scoped admins can see the limits of their own.

  • Managed by: the AD groups whose members manage the scope.
  • Source types the scope can hold.
  • SMB servers its shares may be on. The crawl account signs in to these servers, so list only servers you trust.
  • Crawl accounts its shares may use.
  • May grant users / groups / roles: who its mail and SharePoint sources may give extra access to. guest as a role would make documents visible to everyone.
  • Shortest schedule: how often its sources may be crawled at most.

A scope can only be deleted once its sources are moved or removed.

Credentials Super admins

A credential profile is a crawl account for SMB shares. It holds only the names of the environment variables with the username, password and domain; the values are set on every worker. The default profile is default_credentials in the SMB settings.

A profile can't be renamed, and can't be deleted while a source or scope uses it.

Settings Super admins

The global settings for each source type, as YAML: everything in that type's configuration file except the list of sources, for example which file extensions to skip. A source's own settings override these. Crawls started after saving use the new settings.

Audit log

Every change in the portal: who made it, when, and what changed (open details for before and after). Super admins see everything; scoped admins see changes in their scopes.

Troubleshooting

A job stays queued
No worker has a free slot, or no worker is running. Check the Workers table on Activity (super admins), or ask a super admin.
Test connection fails
Open its Log. Usually the server or share name is wrong, the crawl account can't read the folder, or the account's variables aren't set on the worker.
"This scope can't crawl server …"
The server isn't on the scope's list. A super admin can add it to the scope.
A crawl failed
The Result shows the error and the Log has the details. The next crawl carries on from where the last successful one left off.
A source's documents are still searchable
Disabling keeps them. Use Remove source… to delete them.
I can't see a source, or a page
Scoped admins only see their scopes' sources, and some pages are for super admins only. Group changes apply the next time you sign in.
